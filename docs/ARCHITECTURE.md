# Архитектура Speecher

Обновлено: 2026-07-24 (этапы 0–2, переключаемый ASR-движок `whisper` | `nemotron`, захват — нативный бинарь на Rust вместо PortAudio).

Схема ниже описывает путь **whisper** — дефолтный. Чем от него отличается
путь **nemotron** — в разделе «Два ASR-движка».

## Общая схема

```
 системный звук
      │
      ▼
┌──────────────────────────┐   моно f32 16 кГц в stdout
│ ДОЧЕРНИЙ ПРОЦЕСС capture │ ────────────────┐
│ native/audio_capture     │                 │   downmix и ресемпл — там же,
│ (Rust, WASAPI напрямую)  │                 │   JSON-логи в stderr,
│ моно 16 кГц уже готовы   │                 │   закрытие stdin = стоп
└──────────────────────────┘                 ▼
                              ┌──────────────────────────────┐
                              │ capture-supervisor (поток)   │
                              │ рестарт ребёнка с backoff,   │
                              │ байты → массивы              │
                              └──────┬───────────────────────┘
                                     │ write()
                                     ▼
                          ┌────────────────┐  snapshot/trim ┌───────────────┐
                          │ GrowingAudio-  │◄───────────────│ engine (поток)│
                          │ Buffer         │───────────────►│ LocalAgreement│
                          └────────────────┘                │ -2 + Whisper  │
                                                            └──────┬────────┘
                                                    raw_events     │
                                     ┌─────────────────────────────┘
                                     ▼
                          ┌──────────────────┐ commit → store.append()
                          │ splitter (поток) │──────────► TranscriptStore
                          └──┬────────────┬──┘            (source of truth)
                 sink_events │            │ overlay_events      ▲
                             ▼            ▼                     │ пере-пунктуация
                   ┌──────────────┐  ┌─────────────────┐        │ (12 c, 80 слов)
                   │ output поток │  │ Qt main thread  │  ┌─────┴──────────┐
                   │ консоль ANSI │  │ Overlay: полл   │  │ punctuation    │
                   └──────────────┘  │ 50мс, репейнт 3с│  │ поток (silero) │
                                     │ статус, кнопки  │  └────────────────┘
                                     └───────┬─────────┘
                                             │ LLMTask
                                             ▼
                                     ┌──────────────┐   ┌───────────────────┐
                                     │ llm поток    │──►│ LM Studio REST    │
                                     │  стрим токе- │   │ :1234 (опционален)│
                                     │ нов → сигналы│   └───────────────────┘
                                     └──────────────┘
```

Плюс **asr-loader поток**: окно показывается мгновенно, модель грузится в фоне, прогресс — в статусной строке оверлея; ошибка загрузки не роняет приложение. Если не загрузился не-дефолтный движок, loader пересобирает бэкенд как whisper и пишет причину в статус.

Все потоки — демоны; общий `stop_event` — единый механизм остановки. Закрытие оверлея → `app.quit()` → `aboutToQuit` → `stop_event.set()`. Обратное направление (фатал → закрыть Qt) — QTimer(500 мс). Capture-ребёнок останавливается только `terminate()` от супервизора: его `read()` блокируется в тишине и события не видит.

## Конфигурация

`config/config.toml` → `src/app_config.py` (dataclass-дефолты, tomllib). Отсутствующий файл/ключ = дефолт; кривой тип = дефолт с warning. Ключи 1:1 с полями dataclass'ов.

## Захват: нативный ребёнок

Захват живёт в отдельном процессе — исторически из-за §B1 (PyAudioWPatch портил кучу хост-процесса на простаивающем loopback), теперь просто потому, что это отдельная программа:

- **Ребёнок** — `native/audio_capture` (Rust, WASAPI напрямую). Ни PortAudio, ни Python внутри, поэтому причина §B1 отсутствует, а не маскируется. Отдаёт **готовое моно 16 кГц** в stdout, JSON-строки (`info`/`log`/`fatal`) в stderr, останавливается по закрытию stdin (в тишине он ждёт событие WASAPI и флаги опрашивать не может; это же убивает его, если родитель умер молча). Downmix — среднее по каналам, ресемпл — `rubato::Fft` с состоянием на весь стрим. Детали и протокол — [NATIVE_CAPTURE_RUST.md](NATIVE_CAPTURE_RUST.md).
- **Супервизор** (`capture_base.py` + `rust_capture.py`): рестарт с `restart_backoff_sec`, три быстрых смерти подряд (< 5 с от старта) = постоянная проблема (нет устройства) → fatal и остановка приложения; запись в буфер и в `frame_sink`. Запасного пути на питоновских библиотеках нет: не собран бинарь — сразу fatal с командой сборки.
- WASAPI loopback отдаёт данные только пока что-то рендерится; в тишине кадров нет вообще — и мы их не выдумываем, иначе поехали бы глобальные таймстемпы слов. Ожидание события — с таймаутом 500 мс, это же точка проверки «пора останавливаться».

## Аудиобуфер и глобальное время

`GrowingAudioBuffer` append-only, тримится с головы (`trim_until(global_sec)`), хранит `offset_sec` — сколько секунд уже отрезано. Все таймстемпы слов — **глобальные секунды от начала стрима**: Whisper видит снапшот (локальные времена), движок прибавляет `offset_sec`, после коммита буфер тримится до `последнее_слово.end − margin`. Инвариант: сломаешь глобальность — сломаешь трим, Whisper будет декодировать одно и то же по кругу. Жёсткий cap (60 с) на случай отсутствия коммитов.

## Два ASR-движка

`[asr] engine` выбирает бэкенд (`asr/backends.py`, протокол `ASRBackend`:
`load()` + `run(events, stop_event)`). Общего «движка» над ними нет намеренно —
это разные модели времени.

| | whisper (дефолт) | nemotron |
|---|---|---|
| Как получает аудио | **pull**: снапшоты `GrowingAudioBuffer` раз в `chunk_interval_sec` | **push**: фреймы из `frame_sink` (очередь, дроп при переполнении) |
| Стабилизация | LocalAgreement-2, слово коммитится после двух совпадений | не нужна: вывод append-only, ничего не переписывается |
| События | `commit` + `partial` | только `commit` (промежуточного состояния не существует) |
| Пунктуация | `PunctuationWorker` (silero, 12 с) | нативная, воркер не запускается |
| Гейт тишины | RMS до декода + трим буфера | нет: модель молотит всё, что рендерится |
| Задержка до слова | 2.5–3.5 с | ~0.7 с |
| Языки | 99 | 40 локалей |

Инвариант «`Word.start/end` — глобальные секунды потока» держат оба: whisper
прибавляет `offset_sec` буфера, nemotron считает кадры энкодера по 80 мс от
начала стрима. Замеры и грабли обоих путей — в [MIGRATION_NEMOTRON.md](MIGRATION_NEMOTRON.md).

## Движок whisper: LocalAgreement-2 + тишина

По Macháček et al. (Interspeech 2023). Каждую секунду:

1. **Гейт тишины**: RMS снапшота < `silence_rms_threshold` → декод не запускается, засчитывается «пустой декод».
2. Иначе полный декод буфера (word timestamps, VAD).
3. Самый длинный общий префикс с прошлой гипотезой по `normalize_word` → **commit**; буфер тримится; прошлая гипотеза сбрасывается. Хвост → **partial**.
4. Нет согласия → гипотеза запоминается, partial; буфер > `max_buffer_sec` → force-commit всего, кроме последних N слов.
5. `empty_decodes_before_trim` пустых декодов подряд → буфер подрезается до `silence_keep_tail_sec` (раньше тишина копилась до 60 с и декодилась каждую секунду).

## Адаптер Whisper: язык и галлюцинации

`WhisperAdapter` (`whisper_adapter.py`):

- **Язык**: `"auto"` (дефолт) — sticky: первый декод со словами и `language_probability ≥ sticky_min_probability` фиксирует язык до конца сессии (переопределение каждый цикл на коротком окне даёт «кашу» алфавитов); `"ru"`/`"en"` — жёстко; `""` — старое поведение.
- **Фильтры сегментов**: `no_speech_prob > max` или `avg_logprob < min` → сегмент отбрасывается.
- **Схлопывание повторов**: подряд > `max_word_repeats` одинаковых нормализованных слов режутся (Whisper зацикливается на стационарном шуме).

## TranscriptStore и пунктуация

Стор — потокобезопасный список `(Word, wall_clock)`; **наполняется сплиттером** при commit (не оверлеем — дроп UI-события больше не теряет слова). Оверлей только рендерит (`recent_text`), плюс репейнт-таймер 3 с подхватывает правки пунктуатора.

`PunctuationWorker` раз в 12 с берёт хвост 80 слов, снимает старую краевую пунктуацию, прогоняет через бэкенд и пишет тексты обратно по индексам (append-only ⇒ индексы стабильны; несовпадение числа слов ⇒ тик пропускается). Бэкенд грузится лениво в потоке воркера; ошибка загрузки = «пунктуации нет», не крэш. Бэкенды (`punctuation_backends.py`):

- **silero** (дефолт) — silero-te через torch.hub, CPU, ~50 MB, ru/en/de/es, ставит и пунктуацию, и капитализацию;
- **off**.

Бэкенд `deepmultilingual` (fullstop-punctuation-multilang-large) удалён в фазе 3
миграции на Nemotron: без русского, ~2.1 ГБ, и его пакет тянет `transformers`
ниже `>=5.13`, который нужен движку nemotron.

При `engine = "nemotron"` воркер не запускается совсем (`main.py` логирует это):
пунктуация и регистр приходят от самой модели, повторная пунктуация только
спорила бы с ней.

## LLM-слой

`OpenAICompatClient`: `max_retries=0`, `timeout` из конфига, health-check — отдельным коротким таймаутом (2 с). Все сетевые вызовы — только в llm-потоке; оверлей проверяет доступность в фоновом потоке и получает результат сигналом.

**Провайдер — это строка в таблице, а не класс.** Все поддерживаемые серверы (локальные LM Studio и Ollama, облачные OpenRouter/OpenAI/Anthropic/Gemini/DeepSeek/Groq/Mistral/xAI/Together/Fireworks/Cerebras/DeepInfra, плюс `custom`) говорят на `/chat/completions`, поэтому клиент один, а различия живут в `src/llm/providers.py`: URL, где взять ключ, нужен ли он вообще и можно ли вывести модель из `/models`. Добавить провайдера = добавить строку.

Три вещи, которые в этой таблице сознательно **не** лежат:

- **Ключ.** `config/config.toml` в гите и полон авторских комментариев; ключ туда не попадает никогда. `src/llm/credentials.py` кладёт его в диспетчер учётных данных Windows (`keyring`), при его недоступности — в `%APPDATA%\Speecher\credentials.json`, и в последнюю очередь читает переменную окружения провайдера (`OPENAI_API_KEY`, …), чтобы уже настроенное окружение продолжало работать. В конфиге остаются только `provider` и `model`.
- **Квирки параметров.** Провайдеры расходятся в необязательных полях (`reasoning_effort`, `max_tokens` против `max_completion_tokens`, нестандартный `temperature`). Таблицы квирков нет: `_request` читает текст 400-ки, выбрасывает поле, на которое сервер пожаловался, повторяет один раз и запоминает на сессию. Таблица устарела бы с выходом следующего семейства моделей — сервер единственный, кто знает правду о себе.
- **Автовыбор модели в облаке.** `resolve_model()` берёт модель из `/models` только для локального сервера, где она одна. У каталога из сотен моделей «первая» — случайная, и ответ ею был бы и произвольным, и платным; пустая модель у облачного провайдера — это ошибка с отсылкой в настройки.

Размышления reasoning-моделей глушатся полем `reasoning_effort` (конфиг `llm.reasoning_effort`, по умолчанию `"none"`; `""` — не отправлять поле). Прежний `/no_think`-хак для Qwen3 в новых версиях LM Studio не работает: со включённым размышлением текст уходит в `delta.reasoning_content`, выедает весь `max_tokens`, и наружу приходит пустой ответ — теперь такой случай не молчит, а поднимает ошибку с подсказкой.

Health-check у облака кэшируется на 5 минут: оверлей переспрашивает индикатор раз в 20 с, и без кэша это 180 запросов в час на ровном месте. У локального сервера кэша нет — он реально то поднимается, то падает, а запрос идёт на localhost. `LLMEngine.set_client()` подменяет клиента между задачами, поэтому смена провайдера или вставленный ключ работают без перезапуска приложения.

## Ленивый импорт transformers и потоки

`transformers` — ленивый пакет: имя из `__init__` резолвится импортом того
подмодуля, который его определяет. Два потока, тянущие два имени из **одного**
подмодуля одновременно, — это гонка: проигравший видит модуль, который ещё
исполняется, нужного атрибута там пока нет, и Python сообщает промах как

```
ImportError: cannot import name 'AutoModelForRNNT' from 'transformers'
```

Это читается как сломанная установка или не та версия, и не является ни тем, ни
другим. Ровно это происходило на каждом старте, как только включался перевод:
`main.py` запускает поток asr-loader и поток перевода подряд, ASR-сторона просит
`AutoModelForRNNT`, сторона перевода в этот момент импортирует
`AutoModelForSeq2SeqLM` из того же `models/auto/modeling_auto.py`. ASR-сторона
проигрывала детерминированно (её символ определён в файле позже), nemotron
«не загружался», приложение откатывалось на whisper — и единственным следом
была статусная строка, уезжающая через несколько секунд. Воспроизведено 6 раз
из 6 до фикса и 0 из 6 после.

Поэтому **сам оператор импорта** (и только он) берётся под один процессный
замок — `src/heavy_imports.py`. Кто пришёл первым, платит ~3 с, остальные ждут
полностью инициализированный модуль. Загрузка весов под замок не попадает:
гонка в инициализации модуля, а не в `from_pretrained`, и держать замок через
скачивание значило бы сериализовать загрузку моделей впустую.

Замок работает только если его берут все, поэтому `tests/test_heavy_imports.py`
обходит AST всего `src/` и падает на любом импорте `transformers` вне
`with heavy_imports.transformers():`. Четвёртая точка вызова, добавленная без
охраны, вернула бы всё обратно.

## Тесты

`tests/` (pytest, без GPU/аудио): буфер (трим/офсеты/cap), движок (agreement, force-commit, гейт тишины, трим при пустых декодах), стор (включая конкурентную пере-пунктуацию), адаптер (sticky-язык, фильтры, повторы), воркер пунктуации (контракт счётчика слов, graceful degradation), конфиг (дефолты/коэрция/битый TOML), консольный sink, захват (настоящий супервизор против `fake_capture.py` — тот говорит на протоколе нативного бинаря: рвёт сэмпл между чтениями, падает с `fatal`, молчит как idle loopback).

Нативная часть: `cargo test --manifest-path native\audio_capture\Cargo.toml` — разбор форматов сэмплов (f32/i16/i24/i32, downmix), ресемплер (ratio, DC-уровень, 44.1 кГц), парсер CLI.
