# Архитектура Speecher

Дата: 2026-07-15. Отражает состояние рабочей копии (включая незакоммиченный PunctuationWorker).

## Общая схема

```
                     ┌────────────────────────────────────────────────┐
                     │                 Qt main thread                 │
 системный звук      │  QApplication + Overlay (полл overlay_events   │
      │              │  каждые 50 мс; кнопки → LLMEngine.submit)      │
      ▼              └───────────────▲───────────────────┬────────────┘
┌───────────────┐                    │ overlay_events    │ LLMTask
│ capture поток │                    │                   ▼
│ WASAPI loop-  │            ┌───────┴───────┐   ┌──────────────┐
│ back → 16kHz  │            │ splitter поток│   │  llm поток   │
│ моно float32  │            │ raw → sinks   │   │ LMStudio REST│
└──────┬────────┘            └───────▲───────┘   │ (стрим токе- │
       │ write()                     │ raw_events│  нов → сигна-│
       ▼                             │           │  лы Qt)      │
┌────────────────┐   snapshot ┌──────┴────────┐  └──────────────┘
│ GrowingAudio-  │◄───────────│ engine поток  │
│ Buffer         │  trim_until│ LocalAgreement│──► sink_events ──► output поток
│ (append-only)  │───────────►│ -2 + Whisper  │                    (консоль ANSI)
└────────────────┘            └───────────────┘
                                     ▲
                     ┌───────────────┴────────────────┐
                     │ punctuation поток (каждые 12 с │
                     │ пере-пунктуация 80 слов хвоста │
                     │ TranscriptStore)               │
                     └────────────────────────────────┘
```

Все потоки — демоны; общий `stop_event: threading.Event` — единый механизм остановки. Закрытие оверлея → `app.quit()` → `aboutToQuit` → `stop_event.set()`. Обратное направление (фатал из движка → закрыть Qt) — через QTimer(500 мс), который проверяет `stop_event`.

## Очереди

| Очередь | Размер | Писатель | Читатель | Политика переполнения |
|---|---|---|---|---|
| `raw_events` | 800 | capture, engine | splitter | commit: `put(timeout=0.5)` + лог о дропе; partial/log: `put_nowait` → дроп |
| `sink_events` | 400 | splitter | OutputSink | `put_nowait` → **тихий дроп (включая commit!)** |
| `overlay_events` | 400 | splitter | Overlay (QTimer) | то же |
| LLM queue | ∞ | Overlay | LLMEngine | не переполняется |

## Аудиобуфер и глобальное время

`GrowingAudioBuffer` — ключевая абстракция. Он append-only, но подрезается с головы (`trim_until(global_sec)`), и хранит `offset_sec` — сколько секунд уже отрезано. Все таймстемпы слов в системе — **глобальные секунды от начала стрима**:

1. Whisper получает снапшот буфера, возвращает слова с локальными временами (от нуля снапшота).
2. Движок прибавляет `offset_sec` → глобальные времена.
3. После коммита буфер тримится до `последнее_слово.end − 0.1s` — Whisper больше не декодирует уже закоммиченный звук.

Жёсткий cap 60 с: при переполнении старые сэмплы выбрасываются, offset сдвигается. Инвариант: сломаешь глобальность таймстемпов — сломаешь трим, и Whisper начнёт декодировать одно и то же по кругу.

## LocalAgreement-2 (asr/streaming_engine.py)

По Macháček et al., Interspeech 2023 («Turning Whisper into Real-Time Transcription System»):

1. Каждую секунду — полный декод текущего буфера (word timestamps, VAD-фильтр).
2. Сравнение с предыдущей гипотезой: **самый длинный общий префикс** по `normalize_word` (без пунктуации, casefold, NFKC).
3. Совпавший префикс = стабильные слова → commit-событие; буфер тримится; предыдущая гипотеза сбрасывается (стоит один цикл задержки, зато сравнение всегда на свежем буфере).
4. Несовпавший хвост → partial-событие (жёлтая строка в UI).
5. Страховка: буфер > 25 с без согласия → force-commit всего, кроме последних 6 слов (единственный декод, без подтверждения).

Свойства: галлюцинации не коммитятся (нужно два одинаковых декода подряд), нет фаззи-эвристик слияния, «один поток — одна модель» без разделяемого состояния.

Известная слабость: в тишине `local_words` пуст → `return` до проверки force-commit → буфер не тримится движком и растёт до cap 60 с, и Whisper каждую секунду декодирует всё окно тишины (нагрузка на GPU впустую). VAD-фильтр смягчает, но не убирает декод как таковой.

## TranscriptStore и пунктуация

`TranscriptStore` — потокобезопасный список `(Word, wall_clock_время_приёма)`. Наполняется **только** оверлеем при commit-событиях. Запросы: `all_text()`, `recent_text(chars)`, `words_since_minutes(m)` (по wall-clock), `find_last_question()` (rfind «?»), `context_for_question()`.

`PunctuationWorker` каждые 12 с берёт хвост 80 слов (`get_tail`), прогоняет через `deepmultilingualpunctuation.restore_punctuation` и записывает тексты обратно по индексам (`update_word_texts`). Это корректно только потому, что стор append-only: индексы не сдвигаются. При несовпадении количества слов до/после — тик пропускается.

Нюансы: модель xlm-roberta-large (~2.1 GB, качается с HF при первом запуске; при наличии CUDA грузится на GPU — делит VRAM с Whisper); поддерживает EN/DE/FR/IT — **русского нет**; слова, ушедшие за окно 80 слов между тиками, остаются непунктуированными.

## LLM-слой

`LMStudioClient` — обёртка над OpenAI-совместимым REST LM Studio (`localhost:1234`), model id захардкожен `qwen3.5-9b`, в первый user-месседж подставляется `/no_think` (Qwen3-специфика). `LLMEngine` — очередь задач в одном демон-потоке; колбэки токенов зовутся из LLM-потока, оверлей заводит их в UI через `pyqtSignal`.

Промпты для «ответить на вопрос» и «саммари» сейчас строятся в `Overlay` (`_on_last_q_ai`, `_do_summarize`); одноимённые хелперы в `LMStudioClient` (`answer_question`, `summarize`, `translate`) приложением не используются.
