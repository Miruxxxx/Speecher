Ревью всего проекта (не только диффа). Проверялось на живых запусках: полное приложение (2 прогона), безголовый пайплайн, изолированные компоненты, TTS-тест сквозной транскрипции.

Ядро стриминга (буфер + LocalAgreement-2 + адаптер) спроектировано и написано **хорошо** — чистые инварианты, документированные решения, грамотная работа с backpressure. Обвязка (UI, LLM, main) — рабочий MVP с типовыми дырами. Инфраструктура (тесты, конфиг, зависимости) — отсутствовала (частично добавлена этим ревью: requirements.txt, .gitignore, доки). ## Блокер

### B1. Нативный крэш 0xc0000005 через ~2,5–6 минут работы

Access violation / heap corruption (модуль ntdll.dll, смещение 0xb9d3 — путь RtlFreeHeap), процесс умирает без Python-трейсбека. Именно это выглядит как «проект не заводится»: приложение стартует и через пару минут молча исчезает.

Матрица воспроизведения (все прогоны 2026-07-15):

| Конфигурация | Qt | torch/пунктуация | LLM | Захват | Whisper CUDA | Результат |
|---|---|---|---|---|---|---|
| Полное приложение | ✓ | ✓ | ✓ | ✓ | ✓ | 💥 крэш ~2м20с |
| Полное без пунктуации | ✓ | — | ✓ | ✓ | ✓ | 💥 крэш ~3м |
| Безголовый (захват+движок) | — | — | — | ✓ | ✓ | 💥 крэш ~5м40с |
| **Только захват (8 мин)** | — | — | — | ✓ | — | 💥 **крэш ~7м40с** |
| **Только Whisper-цикл (8 мин, 5438 декодов)** | — | — | — | — | ✓ | ✅ **чисто** |

**Вердикт: виновник — PyAudioWPatch 0.2.12.7 (PortAudio WASAPI loopback).** Изолированный захват-поток, заблокированный в `stream.read()` на простаивающем loopback-стриме (система молчит → фреймы не приходят), уронил процесс без участия Whisper/Qt/torch. Whisper-цикл, наоборот, отработал 5438 декодов без сбоя.

Дополнительная улика: все крэши коррелируют с периодами **тишины** (loopback-стрим без рендер-активности — WASAPI loopback отдаёт фреймы только пока что-то играет; в тишине PortAudio крутит внутренние таймауты, где, видимо, и портится куча). Виртуальное устройство HyperX Virtual Surround может усугублять.

Рекомендации по приоритету:
1. **Изолировать захват в подпроцесс** (самое надёжное): отдельный процесс пишет PCM в shared memory/pipe; супервизор перезапускает его при падении — UI и ASR живут.
2. Обновить PyAudioWPatch / проверить issues по крэшам idle-loopback; попробовать альтернативу (`soundcard`, WASAPI через comtypes).
3. Обходной костыль для проверки гипотезы «крэш в простое»: держать рендер-стрим живым, проигрывая беззвучный поток (loopback перестанет уходить в idle).
4. Watchdog с авто-рестартом пайплайна — до тех пор, пока захват в том же процессе.

## Высокая важность

### H1. Скачущее автоопределение языка → «каша» в транскрипте
`WhisperAdapter(language=None)` — язык переопределяется на каждом ~1-секундном цикле по началу буфера. Воспроизведено: английская TTS-речь частично закоммичена кириллицей (Whisper решил, что это русский с p=0.29). На тихом/шумном звуке язык прыгает en→de→pt→ru.
**Фикс:** зафиксировать язык в конфиге, либо sticky-детекция (определить один раз по первым N секундам речи и держать).

### H2. Зависание UI, когда LM Studio выключен
`LMStudioClient.__init__` принимает `timeout=10.0`, но **не передаёт его в `openai.OpenAI(...)`** — действует дефолт (600 с) и 2 ретрая. `is_available()` зовётся в UI-потоке: при старте (`QTimer.singleShot(500, _check_lm_availability)`) и при каждом клике кнопки (`_start_llm`). Итог: без LM Studio Qt-луп блокируется на секунды (ретраи видны в логе).
**Фикс:** `openai.OpenAI(base_url=..., api_key=..., timeout=2.0, max_retries=0)` + выполнять health-check в фоновом потоке, в UI — только результат через сигнал.

### H3. Сплиттер молча теряет commit-события
`_run_splitter` кладёт события через `put_nowait` и глотает `queue.Full` — включая **commit**. Переполнился `overlay_events` (400) — слова навсегда пропали из стора (и из саммари/вопросов). Движок к своей очереди относится бережнее (commit — блокирующий put с логом), а вся аккуратность теряется на следующем звене.
**Фикс:** для commit — блокирующий put с таймаутом и логом; либо наполнять TranscriptStore напрямую из сплиттера/движка, а не через оверлей (заодно уйдёт зависимость стора от UI).

### H4. В тишине буфер не тримится и декодится целиком каждую секунду
При пустом результате декода `_iterate` делает `return` до проверки `max_buffer_sec` → буфер растёт до cap 60 с, и Whisper каждую секунду декодирует все 60 секунд тишины. Впустую греется GPU, растёт латентность цикла.
**Фикс:** при N подряд пустых декодов тримить буфер (оставляя хвост пару секунд) и/или энергетический гейт перед декодом.

### H5. Вся тяжёлая инициализация — до показа окна
Загрузка Whisper, сетевые проверки HuggingFace и загрузка модели пунктуации (первый раз — 2,1 ГБ!) выполняются до `overlay.show()`. На холодном кэше пользователь минуты смотрит в пустоту — выглядит как «не заводится». Плюс `PunctuationModel()` при обрыве сети может упасть и уронить весь старт, хотя фича опциональная.
**Фикс:** показать окно сразу со статусом «загружаю модели…», грузить модели в фоне; `PunctuationModel` заворачивать в try/except с graceful degradation; после первой загрузки можно выставлять `HF_HUB_OFFLINE=1`.

### H6. Модель пунктуации не поддерживает русский и ест VRAM
`fullstop-punctuation-multilang-large` обучена на EN/DE/FR/IT — для русской речи пунктуация будет мусорной. При этом `deepmultilingualpunctuation` при наличии CUDA грузит xlm-roberta-large (~2 ГБ) на GPU — рядом с Whisper.
**Фикс:** для RU — silero text-enhancement (ru/en/de/es, CPU, лёгкая) или пунктуация батчами через LM Studio; форсировать CPU для пунктуационной модели; сделать выбор модели конфигом.

## Средняя важность

- **M1. Тесты мертвы.** `tests/test_output_sink_unit.py` импортирует легаси `transcript_engine`, который ссылается на удалённую `utils.text.common_prefix_len` → pytest падает на этапе сбора. Новое ядро (движок, буфер, стор) тестов не имеет, хотя тестируется без GPU.
- **M2. Легаси-модули.** `src/transcript_engine.py` (264 строки) и `src/asr/streaming_worker.py` (276 строк) — старый пайплайн, ничем не импортируются, не компилируются с текущим `utils.text`. Удалить (история в git).
- **M3. TranscriptStore не масштабируется по времени сессии.** `all_text()` склеивает весь текст под локом; вызывается на каждый рефреш оверлея (каждый commit/partial) и в `find_last_question`. Часовая сессия ≈ 10⁴ слов — O(N) на каждый чих. Кэшировать конкатенацию/держать rope-структуру, recent_text брать с хвоста без полного join.
- **M4. Конфиг захардкожен.** `name_hint="HyperX"`, модель `base`, `device="cuda"`, `ADD_PUNCTUATION`, URL/модель LM Studio — всё в коде. Папка `config/` существует и пуста. На чужой машине без NVIDIA/с другим устройством проект «не заводится» именно здесь.
- **M5. LMStudioClient: захардкожен `model="qwen3.5-9b"`.** В LM Studio может быть загружена другая модель; есть готовый `loaded_model_id()`, но он не используется. Хелперы `answer_question`/`summarize`/`translate` дублируются самодельными промптами в `Overlay` — два источника правды.
- **M6. LLMEngine нельзя отменить.** Зависший stream (например, LM Studio умер посреди генерации) держит поток до конца; `stop()` ждёт join(10) и бросает. Прокидывать `httpx`-таймауты + флаг отмены между токенами.
- **M7. PunctuationWorker: окно 80 слов.** Слова, проскочившие окно между 12-секундными тиками (быстрая речь > ~6.7 слов/с — редко, но force-commit может выплюнуть пачку), навсегда остаются без пунктуации. Оверлей не перерисовывается после `update_word_texts` — пунктуация проявляется только со следующим commit-событием.
- **M8. Галлюцинации Whisper коммитятся при стабильном шуме.** LocalAgreement защищает от транзиентных галлюцинаций, но на стационарном шуме модель дважды выдаёт одну и ту же галлюцинацию → коммит (наблюдалось в тестовом прогоне). Добавить фильтры `no_speech_prob`/`avg_logprob` на уровне сегментов в адаптере.
- **M9. Скомпилированные .pyc в git.** `git status` показывает изменённые `__pycache__/*.pyc` — они закоммичены в репозиторий. `.gitignore` добавлен этим ревью; осталось `git rm -r --cached "**/__pycache__"`.
- **M10. Ресемплинг чанков без состояния.** `resample_poly` независимо на каждых 2048 фреймах → краевые артефакты фильтра на стыках чанков. На качество ASR влияет слабо, но правильный вариант — стриминговый ресемплер с состоянием (soxr) или ресемплинг снапшота целиком.

## Мелочи

- `task_done()` вызывается в сплиттере и оверлее, но `join()` по очередям никто не делает — мёртвый протокол, убрать.
- `verbose_logs=False` скрывает в консоли log-события движка, включая force-commit — при отладке качества их стоит видеть (сделать флагом запуска).
- `/no_think` и системный промпт — Qwen3-специфика, зашитая в общий клиент.
- `Overlay._handle_asr` не обрабатывает `log`-события (осознанно?), фаталы показываются в LLM-панели — сомнительное место для них.
- INFO-логи httpx/faster_whisper мешаются с ANSI-выводом sink в одной консоли.

## Что сделано хорошо (сохранять при рефакторинге)

- **GrowingAudioBuffer** — образцовая абстракция: глобальное время как контракт, идемпотентный `trim_until`, понятные инварианты, докстринги объясняют «почему».
- **LocalAgreement-2 реализован честно** и без фаззи-эвристик; комментарий в шапке `streaming_engine.py` — готовая документация алгоритма с обоснованием отличий от старого пайплайна.
- Дисциплина событий: разные политики backpressure для commit (ждать) и partial (дропать) — правильное решение.
- Единый `stop_event` + демон-потоки + join с таймаутами на выходе; capture закрывает поток снаружи, чтобы разблокировать зависший `read()`.
- `WhisperAdapter` изолирует faster-whisper от движка (тестируемость), клампит битые таймстемпы.
- PunctuationWorker построен вокруг append-only инварианта стора — редкий случай, когда конкурентная правка текста сделана аккуратно.
