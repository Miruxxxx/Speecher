# Speecher

Десктопное приложение (Windows) для **транскрипции системного звука в реальном времени**: захватывает всё, что играет через колонки/наушники (WASAPI loopback), прогоняет через faster-whisper со стабилизацией LocalAgreement-2 и показывает текст в маленьком always-on-top оверлее с непрозрачной подложкой. По кнопке или хоткею — выжимка разговора и ответ на последний прозвучавший вопрос через LLM: локальную (LM Studio, Ollama) или облачную (OpenRouter, OpenAI, Anthropic, Gemini, DeepSeek, Groq и ещё несколько — список в `src/llm/providers.py`).

Типичный сценарий: онлайн-созвон/лекция → живой транскрипт поверх окон → «Выжимка» (`Alt+5`) подводит итог, «Ответить» (`Alt+Enter`) отвечает на вопрос, который вы прослушали.

## Возможности

- **Живой транскрипт системного звука** — всё, что играет в наушниках, без микрофона и без «шаринга экрана». Два движка на выбор: whisper (99 языков, 2.5–3.5 с до слова) и nemotron (40 локалей, ~0.7 с, пунктуация нативная).
- **Выжимка и ответ на вопрос** — через любую LLM: локальную (LM Studio, Ollama) или облачную по API-ключу. Ответ рендерится с разметкой, а не сырыми звёздочками.
- **Перевод на лету** — локальной MT-моделью, субтитрами: строка попадает в ленту уже готовой и больше не меняется. Оригинал идёт рядом в своём окне.
- **Запись на диск** — JSONL-журнал пишется по ходу сессии, переживает падение, восстанавливается реплеем. Экспорт в `.md` / `.txt`, копирование выделения.
- **История выжимок**, автосаммари по интервалу, уведомление когда окно скрыто.
- **Глобальные хоткеи** — работают при скрытом окне; занятую комбинацию приложение переживает без падения.

## Стек

| Слой | Технология |
|---|---|
| Захват звука | нативный бинарь на Rust (WASAPI loopback напрямую) **в отдельном процессе** с супервизором и авто-рестартом; downmix и ресемплинг → 16 kHz там же |
| ASR | два переключаемых движка (`[asr] engine`): **whisper** (по умолчанию) — faster-whisper `large-v3-turbo` на CUDA fp16 + LocalAgreement-2 с гейтом тишины и фильтрами галлюцинаций; **nemotron** — `nvidia/nemotron-3.5-asr-streaming-0.6b`, cache-aware стриминг, ~0.7 с до слова, пунктуация нативная |
| Пунктуация | silero-te (ru/en/de/es, CPU) — только для движка whisper; nemotron пунктуирует сам |
| LLM | любой OpenAI-совместимый провайдер: локальный (LM Studio, Ollama) или облачный по API-ключу |
| UI | PyQt6 — frameless-оверлей по дизайн-системе ([docs/DESIGN_SYSTEM.md](docs/DESIGN_SYSTEM.md)): два режима 600 × 340 / 360 × 200, IBM Plex, SVG-иконки; плюс консольный вывод |

Python 3.11, только Windows (WASAPI loopback).

## Установка

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install torch --index-url https://download.pytorch.org/whl/cu128
.venv\Scripts\python -m pip install -r requirements.txt
cargo build --release --manifest-path native\audio_capture\Cargo.toml
```

torch ставится первым и отдельным индексом: с PyPI приедет `+cpu`, и движок
nemotron работать не будет (подробности — в шапке `requirements.txt`).

Последняя строка собирает захват звука — без неё приложение стартует, но сразу
скажет, что бинарь не найден. Нужен [rustup](https://rustup.rs) с
`stable-x86_64-pc-windows-msvc`; линкер берётся из Visual Studio Build Tools.

Требования:
- NVIDIA GPU + драйвер для faster-whisper на CUDA (либо `device = "cpu"` + `compute_type = "int8"` в конфиге — медленнее).
- Для LLM-фич: либо запущенный [LM Studio](https://lmstudio.ai) с загруженной моделью и сервером на :1234 (по умолчанию), либо API-ключ облачного провайдера — он вставляется в «Настройки → Модель ИИ» и хранится в диспетчере учётных данных Windows, а **не** в `config.toml` (файл в гите). Без того и другого всё работает, LLM-кнопки покажут предупреждение.
- Первый запуск скачивает модели: whisper `large-v3-turbo` (~1.6 GB с HuggingFace) и silero-te (~50 MB). Окно появляется сразу, прогресс виден в статусной строке оверлея.

## Конфигурация

Все настройки — в [config/config.toml](config/config.toml) (файл можно удалить — приложение запустится на дефолтах). Ключевое:

- `[audio] device_hint` — подстрока имени устройства вывода, чей loopback слушаем (`"HyperX"`); пусто = устройство по умолчанию. `source = "mic"` переключает захват на микрофон, `binary` — путь к бинарю захвата, если он лежит не в дереве проекта.
- `[asr] engine` — `whisper` (по умолчанию) или `nemotron`; неизвестное значение → `whisper` с предупреждением. Ключи ниже относятся к whisper-пути.
- `[asr.nemotron]` — читается только при `engine = "nemotron"`: модель, `dtype` (`float32` по умолчанию — fp16 экономит VRAM, но декодирует вдвое медленнее), `lookahead_tokens` `0/3/6/13` → задержка 80/320/560/1120 мс.
- `[asr] model / device / language` — модель Whisper, cuda/cpu и режим языка:
  - `"auto"` — определить по первой уверенной речи и зафиксировать (по умолчанию);
  - `"ru"`, `"en"`, … — жёстко;
  - `""` — переопределять каждый цикл (не рекомендуется: даёт «кашу» алфавитов).
- `[asr.filters]` — пороги отбраковки галлюцинаций (`no_speech_prob`, `avg_logprob`), схлопывание повторов, гейт тишины.
- `[punctuation] backend` — `silero` (ru/en/de/es, CPU) / `off`. При `engine = "nemotron"` воркер не запускается вообще.
- `[llm]` — `provider` (кого спрашивать), `model`, таймауты. У локального сервера `model = ""` берёт загруженную модель; у облачного модель надо выбрать. API-ключ сюда не пишется никогда.
- `[translate]` — перевод на лету. `backend`: `nllb` (одна модель на все языки, ~2.5 ГБ при первом включении) / `opusmt` (одна пара, ~300 МБ, нужны `sentencepiece` и `sacremoses`) / `off`. `enabled` — включён ли на старте, `target` — язык перевода, `show_source` — показывать ли окно с живым оригиналом. Перевод идёт мимо LLM-провайдера: очередь кнопок «Ответить» и «Выжимка» остаётся свободной.

## Управление оверлеем

- Перетаскивание — зажать ЛКМ в любом месте титульной строки, кроме двух её кнопок; двойной клик переключает обычный режим (600 × 340) и компактный (360 × 200).
- Три индикатора в шапке: захват звука (волна = звук идёт, ровная линия = тишина, перечёркнутая = ошибка), запись на диск, состояние модели (офлайн / онлайн / думает / пишет / ошибка). Индикаторы только показывают — кликать их не нужно.
- Кнопки: **Ответить** (на последний вопрос), **Выжимка** (за интервал из настроек), **Последний вопрос** (показать). В шапке справа — меню сессии (экспорт, остановка записи, история выжимок, хоткеи, настройки) и крестик.
- Хоткеи работают и при скрытом окне: `Alt+Space` — показать/скрыть, `Alt+Enter` — ответить, `Alt+5` — выжимка, `Alt+Q` — последний вопрос, `Alt+H` — история выжимок, `Alt+R` / `Alt+P` — запись и пауза, `Alt+T` — перевод на лету. `Esc` закрывает карточку и меню, но не окно.
- Перевод на лету (`Alt+T` или меню сессии) работает как субтитры: речь режется на сегменты (предложение / пауза), сегмент переводится целиком и падает в ленту **готовой строкой, которая больше никогда не меняется** — ничего не гаснет и не перевёрстывается задним числом. Оригинал при этом никуда не девается: он идёт своей обычной лентой в отдельном маленьком окне «Оригинал» — строки в нём остаются и прокручиваются как обычно (закрывается крестиком, возвращается из меню сессии). Оригинал остаётся в транскрипте, в журнале и в `.txt`-экспорте; markdown-экспорт кладёт перевод цитатой под абзацем. Переключение действует на сессию и не трогает `config.toml`.
- Настройки (устройство вывода, движок, язык, провайдер и модель LLM, интервал выжимки, перевод и его язык, хоткеи) пишутся обратно в `config/config.toml`. Исключение — API-ключ: он идёт в диспетчер учётных данных Windows (или в `%APPDATA%\Speecher\credentials.json`, если keyring недоступен), потому что `config.toml` лежит в репозитории. Кнопка «Проверить» рядом с полем сразу говорит, работает ли ключ; «Список моделей» подтягивает каталог провайдера. Смена провайдера применяется без перезапуска.

## Статус

Функционально всё, что задумывалось, работает: захват, оба ASR-движка, LLM с
любым провайдером, перевод, персист, экспорт, хоткеи, настройки в UI.
298 тестов (`pytest tests/`, без GPU и звука) плюс 14 в Rust-бинаре.

Что стоит между этим и версией 1.0 — честно, по убыванию важности:

1. **Установка — это сборка из исходников, а не установка.** venv, torch с
   отдельного индекса, rustup, `cargo build`, Visual Studio Build Tools. Для
   десктопного приложения версии 1.0 нужен собранный `.exe` с предсобранным
   бинарём захвата — либо явная пометка, что это dev-сборка.
2. **Дефолтный движок не проверен на живой речи.** `config.toml` ставит
   `nemotron`, но до 2026-07-27 он молча откатывался на whisper из-за гонки
   ленивых импортов transformers (починено, см. `src/heavy_imports.py`) — то
   есть у пути, который задуман основным, ноль часов реального использования.
   К тому же дефолт в коде (`whisper`) и дефолт в конфиге (`nemotron`)
   расходятся: их надо свести после прогона на настоящей речи.
3. **Тихая деградация и отсутствие логов на диске.** Откат движка, сорвавшийся
   журнал, неработающий ключ — всё это сообщается строкой статуса, которая
   уезжает за несколько секунд, а `logging` пишет только в stderr. Приложение,
   которое работает часами в фоне, должно оставлять после себя лог-файл.
4. **Нет CI.** Тесты есть и быстрые (4 с), но никто не гоняет их автоматически.
5. **Дефолты из личной машины.** `device_hint = "HyperX"` — это конкретные
   наушники автора, а не разумное значение по умолчанию.

## Структура проекта

```
assets/
  fonts/                   # IBM Plex Sans/Mono (SIL OFL) — грузятся в рантайме
config/
  config.toml              # все настройки (TOML)
native/
  audio_capture/           # захват звука на Rust (WASAPI): бинарь + его тесты
src/
  main.py                  # сборка пайплайна: окно сразу, модели в фоне
  app_config.py            # загрузка config.toml поверх дефолтов
  heavy_imports.py         # общий замок на ленивый импорт transformers из потоков
  audio/
    rust_capture.py        # спавн/рестарт нативного ребёнка, байты → буфер
    capture_base.py        # политика рестарта, запись в буфер/frame_sink
    buffer.py              # GrowingAudioBuffer: append-only + head-trim
  asr/
    backends.py            # протокол ASRBackend + выбор движка по [asr] engine
    whisper_backend.py     # pull-путь: снапшоты буфера → StreamingASREngine
    streaming_engine.py    # LocalAgreement-2 + гейт тишины (поток engine)
    whisper_adapter.py     # faster-whisper → Word[]; sticky-язык, фильтры галлюцинаций
    nemotron_backend.py    # push-путь: фреймы из frame_sink → стриминговый RNN-T
    punctuation_backends.py# silero-te (CPU) | off
    punctuation_worker.py  # фоновая пере-пунктуация хвоста транскрипта (только whisper)
    events.py              # ASREvent (commit/partial/log/fatal), Word
  store/
    transcript_store.py    # потокобезопасный стор слов + запросы (вопрос/период)
  llm/
    engine.py              # очередь LLM-задач в отдельном потоке
    providers.py           # реестр провайдеров: 2 локальных + 12 облачных + custom
    credentials.py         # API-ключи: диспетчер учётных данных → файл → env
    openai_client.py       # один OpenAI-совместимый клиент на всех, без ретраев
  translate/
    backends.py            # nllb (все языки одной моделью) | opusmt (пара) | off
    segments.py            # речь → сегменты (предложение/пауза), ключ = индекс слова
    worker.py              # свой поток: сегмент → перевод → готовая строка ленты
    store.py               # append-only строки перевода + запись в журнал
    languages.py           # таблица языков и эвристика алфавита (без Qt/torch)
  ui/
    overlay.py             # оверлей: раскладка, экраны, действия, меню сессии
    theme/                 # токены, шрифты, SVG-иконки, QSS
    widgets/               # индикаторы, кнопки, лента транскрипта, карточки
    windows/               # настройки, история выжимок, уведомление, онбординг
    markup.py              # markdown из ответов модели → рич-текст карточки
    transcript_model.py    # слова → реплики с таймстемпами (без Qt)
    hotkeys.py             # глобальные хоткеи (RegisterHotKey)
    output_sink.py         # консольный рендер (ANSI), параллельно оверлею
  utils/                   # normalize_word, LatencyTracker
tests/                     # pytest: buffer, engine, store, adapter, worker, config
scripts/                   # ручные утилиты (список устройств, уровни звука)
docs/                      # архитектура, код-ревью, роадмап
storage/transcripts/       # (зарезервировано под персист транскриптов)
```

Подробности потоков и алгоритма — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Известные проблемы

1. Захват требует собранного бинаря (`cargo build --release …`): без него приложение сразу скажет, чего не хватает, — запасного пути на питоновских библиотеках нет. Раньше эту роль играл PyAudioWPatch, который портил кучу своего процесса после нескольких минут простаивающего loopback-стрима (история — [docs/CODE_REVIEW_2026-07-15.md](docs/CODE_REVIEW_2026-07-15.md) §B1); он удалён вместе с этим багом.
2. WASAPI loopback отдаёт фреймы только пока что-то играет: в полной тишине захват «молчит» — это нормально.
3. Модель `large-v3-turbo` на слабом GPU может не укладываться в 1-секундный цикл — поставьте `small`/`base` в конфиге.

## Диагностика

- Список устройств: `python scripts/list_audio_devices.py`
- Долгий прогон захвата: `python scripts/capture_soak.py --seconds 900`
- `[ui] console_verbose_logs = true` — показывает log-события движка (рестарты захвата, force-commit) в консоли.
- Тесты: `python -m pytest tests/ -q`
- Крэши смотреть в Windows Event Log: `Get-WinEvent -FilterHashtable @{LogName='Application'; ProviderName='Application Error'} | ? Message -match 'python'`
